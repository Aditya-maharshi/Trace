## 2026-10-04 - Optimize aggregateAttributions Transaction Fetching
**Learning:** In tracing domains processing blockchain transactions (`aggregateAttributions`), executing sequential data fetching calls (e.g., `fetchTxs(addr)`) within deeply nested loops (iterating over multiple `paths` and then over each non-terminal `hop` per path) results in a severe N+1 network/cache request bottleneck that inflates the time-to-first-byte for attribution responses. The performance hit scales multiplicatively with path count and path depth.
**Action:** Extract unique requisite parameters (e.g., wallet addresses) upfront and fetch them concurrently using `Promise.all` before passing an aggregated dictionary/map of pre-fetched data to downstream iterative scoring functions. Ensure subsequent iteration only operates on properties within its respective scope to maintain correctness.
