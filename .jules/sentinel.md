## 2024-10-16 - Prevent IDOR when fallback to Supabase Admin is used
**Vulnerability:** IDOR in API route handlers (`apps/api/app/api/cases/[id]/evidence/route.ts`). Users could access or modify evidence for cases they did not own because the endpoint relied on an admin fallback `getSupabaseAdmin()` without enforcing application-level authorization.
**Learning:** `getSupabaseAdmin()` bypasses Row Level Security (RLS). If an endpoint falls back to using the admin client (e.g., if a user client cannot be instantiated), the API route itself MUST explicitly retrieve the resource and validate ownership using `assertCaseAccess()` before completing the request or calling any admin-backed mutation functions like `pinEvidence()`.
**Prevention:** Always implement explicit application-level authorization checks (e.g., fetching the target resource and verifying the user has access) in API endpoints before proceeding with any action, especially if the underlying logic uses `getSupabaseAdmin()`.
