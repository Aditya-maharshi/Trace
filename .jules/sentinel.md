## 2026-10-11 - Critical IDOR via Admin Fallback Pattern
**Vulnerability:** Found a critical Insecure Direct Object Reference (IDOR) vulnerability in `apps/api/app/api/cases/[id]/evidence/route.ts` where fetching case evidence and pinning evidence bypassed row-level access controls.
**Learning:** The vulnerability existed because the code used an unsafe fallback pattern `getSupabaseUserClient(...) || getSupabaseAdmin()`. The admin client bypassed Row Level Security (RLS) entirely. Furthermore, the `assertCaseAccess` helper function was completely missing on these operations, allowing any authenticated user to view or modify evidence for cases they didn't own.
**Prevention:** Never use `getSupabaseAdmin()` as a fallback for user-driven API actions. Always instantiate the Supabase client using `getSupabaseUserClient(authHeader)` to enforce RLS. Ensure that `assertCaseAccess(caseRow, userId)` is explicitly invoked and its result checked before performing operations on specific objects.
