## 2024-05-27 - Unused Security Function Leading to IDOR
**Vulnerability:** The API endpoint for case evidence (`apps/api/app/api/cases/[id]/evidence/route.ts`) imported the `assertCaseAccess` function but did not invoke it in either the `GET` or `POST` request handlers. This omission created an Insecure Direct Object Reference (IDOR) vulnerability, as any authenticated user could iterate through `id` parameters to read or modify evidence for cases they did not own or have access to.
**Learning:** Having security verification functions like `assertCaseAccess` available is meaningless unless they are explicitly called. The presence of the import statement alone is not sufficient protection and can lead to a false sense of security.
**Prevention:** Developers must enforce the actual invocation of authorization checks on every relevant route handler (e.g., within `GET`, `POST`, `PATCH`, `DELETE`). Automated code reviews and static analysis should ideally flag imported but unused security functions.
