## 2024-05-18 - Prevent RLS Bypass via getSupabaseAdmin fallback
**Vulnerability:** A critical IDOR/Privilege Escalation vulnerability existed in several `/api/cases/[id]/*` endpoints. These endpoints attempted to load a user context via `getSupabaseUserClient()`, but incorrectly included a fallback `|| getSupabaseAdmin()` if the user client failed to initialize or was missing.
**Learning:** `getSupabaseAdmin()` uses the `SUPABASE_SERVICE_ROLE_KEY`, which entirely bypasses Row Level Security (RLS) policies in the database. Using this as a fallback on a user-driven endpoint essentially granted any unauthenticated or unauthorized user full administrative database access when accessing those endpoints.
**Prevention:** Never use `getSupabaseAdmin()` as a fallback for user-driven actions. Always strictly rely on `getSupabaseUserClient()` with the provided authorization header to ensure that database queries are scoped to the user's permissions and RLS is enforced. Service-role clients should only be used for automated background tasks or specific scenarios where overriding RLS is explicitly required and verified.
