## 2026-10-09 - Address IDOR and Privilege Escalation in Evidence Route\n**Vulnerability:** IDOR vulnerability in `apps/api/app/api/cases/[id]/evidence/route.ts` where users could fetch and mutate case evidence without being the case owner or assigned analyst, compounded by privilege escalation through `getSupabaseAdmin` fallback.\n**Learning:** The fallback to `getSupabaseAdmin` when `getSupabaseUserClient` failed (e.g. invalid auth token or intentionally unauthenticated) completely bypassed Row Level Security for user-driven endpoints. Additionally, relying solely on fetching evidence by `case_id` without authorizing the specific user allows horizontal privilege escalation (IDOR).\n**Prevention:** Never use `getSupabaseAdmin()` for user-driven data retrieval and mutations, always pass user auth context (`getSupabaseUserClient`). Ensure `assertCaseAccess` is evaluated for all case-specific endpoints.
